## 主题：挂号费分级定价 + 药品效期管理与过期自动下架（P8）

### 需求来源
用户答辩前提出两个改造：
1. 每个医生职称不同，挂号收费标准应有差异 → 挂号费按医生分级定价
2. 药品缺生产日期/有效期 → 补效期字段 + 过期自动下架 + 推送到工作台处理

### 关键决策：增量补丁而非重建库
集成测试 `MiddlewareIntegrationTest` 断言「35 并发恰好成功 28 个」，该数字取决于

重建数据库会改变种子状态 → 断言失败。

## 追加：28/7 断言问题的机制复核（关键补充发现）

读 `RegistrationService.createRegistration()` 全流程后确认：断言数字**完全由排班剩余号源决定**，
链路为 `schedule.remain_num` →（第139行 `setIfAbsent("schedule:stock:{id}", remainNum)`）→
Redis →（Lua `GET/<=0?/-1/DECR`）→ 成功次数 → 断言。

**新发现：该用例本身不可重复执行（不只是种子数据问题）**
跑完一次后：① 排班 2 的 `remain_num` 被条件更新减到 0；② patients 100~134 在排班 2 留下
status=1 的挂号。第二次再跑：全部命中「您已挂过该号源」+ Redis 号源为 0 → `succ=0` → 必红。
结论：**即使退回旧 init.sql 的 28 状态，也必须"恢复库 + FLUSHDB"才能跑绿**，
所以「让测试自己摆数据」（方案甲）才是真正解法，方案乙只治标。

另注：`RegistrationService` 第 148-155 行对 Lua 返回值的处理 —— `-1` 抛「号源已满」、
`-2` 抛「号源缓存异常」，因此**若 Redis 无该 key 且 setIfAbsent 未生效，会报缓存异常而非号源已满**。

## 🔴 演示现场 bug：多标签页登录不同角色 → 医生点接诊报「权限不足」

## 经验记录（踩过的坑）
1. **有两个 `init.sql` 是灾难**——多脚本并存会让重置路径分裂。**一个项目只能有一个重置脚本**，
   生成器输出原地覆盖，不要 patch / backup / init_full 三件套。
2. **用户给的 `reset.bat` 是权威重置入口**，我手工敲等价命令四五遍是浪费——**重置前先找现成脚本**。
3. **MyBatis-Plus 默认 `updateStrategy = NOT_NULL`**：想把字段清成 NULL 会静默失败，
   必须显式 `@TableField(updateStrategy = FieldStrategy.IGNORED)`。
4. **Controller 逐字段构建实体的写法**：新增字段后若忘了补 `setXxx()`，接口永远存不上值，
   且不报错——改实体字段时**必须同步检查 Controller 的 create/update**。
5. **测试断言依赖种子数据状态**时，改数据比改测试更便宜——但要保证 `reset.bat` 每次跑测试前都执行。
6. **HTTP 403「权限不足」先怀疑前端 token 串号**，不要一上来查后端权限代码。用 curl 直打接口
   验证「谁发的 token」比在浏览器里猜快得多。
7. **多个无痕窗口 ≠ 多个身份**（Chrome 官方：隐私会话在窗口间延续）。要 3 个身份需
   普通+无痕+另一浏览器。
