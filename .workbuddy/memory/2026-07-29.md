# 2026-07-29 工作日志

## AES 解密 BadPaddingException 修复

### 根因
init.sql 中的 medical_record.content 密文是用**旧密钥**加密的：
- 旧密钥: `clinic-aes-key-32bytes-secret!!` (AES-128, byte[16], 只取前16字节 → `clinic-aes-key-3`)
- 新密钥: `clinic-aes-secret-key-for-256bit` (AES-256, byte[32])

AES-128→256 升级时改了密钥字符串，但 init.sql 种子数据的密文没跟着重新加密。

### 额外发现的 bug
`getKey()` 方法: `byte[32]` buffer 但 `Math.min(srcBytes.length, 16)` 只复制了16字节。
升级时 `byte[16]→byte[32]` 改了，但 `Math.min` 参数没跟着改，导致32字节buffer只有前16字节有值。

### 修复内容
1. **AesUtils.java** 第78行: `Math.min(srcBytes.length, 16)` → `Math.min(srcBytes.length, 32)`
2. **AesUtils.java** 注释: "16 字节" → "32 字节" (3处)
3. **init.sql** 3条 medical_record.content 用新AES-256密钥重新加密
4. **数据库** 3条记录的 content 字段已 UPDATE 为新密文

### 验证
- Python 脚本用新密钥(32字节)解密3条记录全部成功
- 测试文件 AesUtilsTest.java 无需修改（运行时加密解密，不硬编码密文）
- 需重启后端使 AesUtils.java 生效
