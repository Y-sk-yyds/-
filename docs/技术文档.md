# 社区诊所门诊诊疗管理系统 — 技术文档

## 一、项目概述

本系统面向社区诊所，实现从患者建档、医生排班、线上挂号、医生接诊、处方开具、收费结算到电子病历的全流程数字化管理。采用前后端分离架构，引入 Redis 分布式锁、Lua 原子脚本、RabbitMQ 异步消息、AES 病历加密等中间件技术，解决高并发挂号超卖、药品库存并发扣减、复诊异步提醒等核心业务痛点。

- **技术栈**：Spring Boot 3.2 + Vue3 + MyBatis-Plus 3.5 + MySQL 8.4 + Redis 7 + RabbitMQ 3
- **前端端口**：5173 | **后端端口**：8080
- **权限模型**：RBAC（ADMIN / DOCTOR / CASHIER 三角色）

## 五、中间件技术实现

### 5.1 Redis Lua — 挂号防超卖

**场景**：早高峰多名患者同时抢同一医生的号源，30 个号源，50 人点击。

**传统做法的问题**：

```sql
-- 两步操作非原子，并发时产生超卖
SELECT remain_num FROM schedule WHERE id = ?;  -- 读到 1
UPDATE schedule SET remain_num = remain_num - 1 WHERE id = ?; -- 两个线程都执行
```

**本系统方案**：将"检查库存→扣减"的原子判断下沉到 Redis，利用 Lua 脚本的原子性保证串行执行。

```
35 请求 → Redis Lua (串行排队处理)
        → 30 个成功（DECR）
        → 5 个拒绝（号源已满）
        → MySQL 仅做持久化（无并发争抢）
```

Lua 脚本核心逻辑（RegistrationService.java）：

```lua
local stock = redis.call('GET', KEYS[1]);   -- 读取库存
if not stock then return -2 end;             -- key不存在
stock = tonumber(stock);
if stock <= 0 then return -1 end;            -- 已无号
redis.call('DECR', KEYS[1]);                 -- 原子减1
return stock - 1;                             -- 返回剩余
```

**验证结果**：集成测试 35 并发抢 30 号源 → 成功 30，拒绝 5，0 超卖。

### 5.2 Redis SETNX — 药品库存并发锁

**场景**：多张处方同时包含同一药品，并发扣减库存。

**实现**（PrescriptionService.deductStock）：

```
获取锁 SETNX drug:lock:{id} "1" EX 3
  ↓ 成功
查询库存 SELECT current_stock FROM drug_stock WHERE drug_id = ?
  ↓ 库存充足
UPDATE drug_stock SET current_stock = current_stock - 1 WHERE drug_id = ? AND current_stock >= ?
  ↓
释放锁 DEL drug:lock:{id}
```

使用 StringRedisTemplate 避免 JSON 序列化问题。Key 自动过期 3 秒兜底，防死锁。

**验证结果**：集成测试 30 线程并发抢 5 盒库存 → 成功 5，失败 25，库存归零，无超扣。

### 5.3 RabbitMQ — 复诊异步提醒

**场景**：医生完成就诊时填写"2 周后复诊"，系统需要创建提醒记录，但不应该阻塞前端。

**实现**：

```
前端点击"完成就诊"
  → 后端保存就诊记录
  → 发送 MQ 消息 (routingKey: reminder)
  → 前端立即返回（不等待）
  → ReminderConsumer 后台消费 → 写入 reminder 表
```

**验证结果**：集成测试前端 92ms 响应，MQ 在后台消费成功，入 reminder 库。

### 5.4 AES-256 — 病历加密存储

**场景**：电子病历涉及患者隐私，数据库不能存明文。

**实现**（AesUtils.java + MedicalRecordService）：

- 算法：AES-256 / CBC 模式 / PKCS5Padding
- 密钥：配置文件注入（aes.secret-key），16 字节
- IV：固定向量 "ClinicSystem-IV-"
- 流程：写入时 `encrypt(明文)` → 密文入 MySQL；读取时 `decrypt(密文)` → 返回前端

**验证结果**：单元测试验证加密解密一致性、篡改密文拒绝、长文本/空字符串正确处理。

## 七、关键业务流程

### 7.1 挂号 → 接诊 → 处方 → 收费 → 病历（完整链路）

```
1. 患者挂号 POST /api/registrations
   → Redis Lua 原子扣减号源 → MySQL 写入挂号记录

2. 医生开始接诊 PUT /api/consultations/{id}/start
   → 校验挂号是否属于当前医生 → 创建就诊记录

3. 医生完成接诊 PUT /api/consultations/{id}/complete
   → 填写主诉/诊断/医嘱 → 自动生成 AES 加密病历 → MQ 发送复诊提醒

4. 医生开具处方 POST /api/prescriptions
   → Redis SETNX 锁定药品库存 → 扣减库存 → 写入处方+药品明细 → 自动生成待收账单

5. 收银员收费 PUT /api/bills/{id}/pay
   → 选择支付方式 → 更新账单状态 → 更新处方状态

6. 查看病历 GET /api/records/{id}
   → AES 解密 → 返回明文
```

## 十、项目亮点总结

1. **Redis Lua 原子扣减**：挂号热点从 MySQL 行锁迁移到 Redis，串行排队防超卖
2. **Redis SETNX 分布式锁**：药品库存并发扣减，自旋重试防死锁
3. **RabbitMQ 异步解耦**：复诊提醒不阻塞前端，92ms 内返回
4. **AES-256 病历加密**：CBC 模式加密存储，患者隐私保护
5. **RBAC 权限隔离**：三角色 + 路由守卫 + 后端数据隔离
6. **全流程闭环**：挂号→接诊→处方→收费→病历 完整链路跑通
7. **19 个全绿测试**：单元 + 集成，覆盖安全、业务、中间件
